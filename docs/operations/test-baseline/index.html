Quality Studio / QS-66 / Decision dossier

A test baseline that stays green

The current acceptance surface is red for several different reasons: one real production-build regression, machine-dependent checks mixed into routine commands, and missing host prerequisites. The sustainable answer is a tiered gate with explicit fixtures, pinned tools, and a measured coverage ratchet.

Repository state 3e0b655 Observed 11 August 2026 Decision decided: Option B (11 August 2026) Recommended option B

Current gate: fail, and the failure is reproducible

  • The production Angular build exits 1: the initial bundle is 494.94 kB against the existing 480 kB error budget.
  • An unfiltered Release .NET run exits 1 under host load: the dashboard projection took 354 ms against a 150 ms timing assertion.
  • The root dev-stack suite exits 1 on Linux: 2 of 5 cases fail because a Windows npm.cmd fixture is spawned as a Linux executable and returns EACCES.
  • The default Angular test command exits 1 when no system Chrome is installed, even though a compatible Playwright Chromium is already cached elsewhere on the host.

Deterministic assertions are largely healthy once their environment is explicit

The filtered .NET lane passed 175 tests with one opt-in live review skipped. Both declared machine-bound .NET tests passed when isolated. Angular passed all 17 Jasmine cases when CHROME_BIN pointed at the cached Chromium. The repository security scan passed with 268 files, zero new findings, and pinned Gitleaks 8.24.2.

QS-57 delivery state: useful evidence, no repository baseline

The QS-57 worktree is clean at the same commit 3e0b655 and has no diff from this task. Its 34 collected files show a prepared green development build and test run. They also preserve an earlier review failure caused by absent frontend/node_modules. QS-57 did not run the production frontend build, did not add a CI contract, and did not deliver status.md or a repository change. This dossier uses its evidence but does not treat the baseline as delivered.

01Decision requested

Approve Option B and Slices 1 through 5 as one ordered improvement wave

Make a deterministic, clean-checkout PR gate mandatory. Keep host integration in its own controlled job. Run timing, real-service, and live-agent checks as release canaries with retained measurements. Preserve the 480 kB product budget, repair the current regression, and ratchet measured coverage from the first generated baseline.

This decision does not declare today's repository green. It defines the shortest contract that can become green without hiding product or infrastructure failures.

06Sustainable baseline contract

Required PR: portable

  • Pin .NET 10.0.301 and Node 22.
  • Restore from lock files and build Release.
  • Run xUnit with Category!=MachineBound.
  • Run the production Angular build. Keep the 480 kB limit.
  • Provision pinned Chromium, then run all Angular specs.
  • Run pinned Gitleaks with explicit provisioning.
Blocked today by the production bundle.

Required PR: host integration

  • Run the dev-stack suite separately on Linux and Windows.
  • Use dynamic ports and OS-neutral fixture executables.
  • Persist stdout and stderr for every early exit.
  • Run without depending on a warmed package or browser cache.
Blocked today by the npm.cmd fixture.

Coverage ratchet

  • Generate Cobertura for both .NET assemblies and lcov for Angular.
  • Fail if either report is missing or unreadable.
  • Commit the first measured baseline by project and feature area.
  • Fail subsequent PRs on a decrease. Raise the baseline only with added tests.
No arbitrary percentage before measurement.

Release canary

  • Run both MachineBound xUnit checks.
  • Run both frontend performance stages with retained JSON and screenshots.
  • Run the live-agent test when review execution changes.
  • Report dependency-unavailable separately from product-failed.
Release-blocking, not PR-timing noise.

Fixture and test-data rules

  • Fresh checkout is the reference. CI installs frontend dependencies and the browser. A warm local cache may speed the run but may not change the result.
  • Version every external format fixture. Audit, SARIF, coverage, review response, and API contract documents carry a source tool/version and a small validity assertion.
  • Centralize temporary repositories. One builder owns Git identity, fixed timestamps, line endings, cleanup, allowed roots, and failure diagnostics.
  • Share API contract builders. Replace repeated inline dashboard, review, and repository payloads in TypeScript and Node scripts with typed builders or schema-validated JSON fixtures.
  • Keep performance corpus generation outside the measured interval. Store the measured browser/runtime/host metadata with every canary result.
  • No silent quarantine. Any temporary quarantine has an owner, linked defect, evidence, and expiry. Portable assertions are never retried to manufacture green.

Parallelization boundary

09Definition of green

  • The production Angular bundle is within the existing 480 kB error budget. A development build cannot satisfy this condition.
  • The required portable .NET, Angular, security, and host-integration jobs pass from a clean checkout without inherited caches.
  • No machine-bound timing assertion runs in the portable .NET command.
  • Linux and Windows dev-stack jobs use isolated ports and platform-neutral fixtures.
  • .NET Cobertura and Angular lcov artifacts exist, parse, and do not fall below the committed ratchet.
  • The release canary is recent and green for changes affecting hierarchy performance, browser performance, repository switching, or live review execution.
  • Failures remain visible. Missing tools and unavailable networks are classified separately, not converted into passing product results.
  • README and contributor commands name the same checks that branch protection requires.
