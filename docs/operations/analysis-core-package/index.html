Architecture decision and first slice · QS-91 · 27 August 2026

Quality analysis belongs in the process that already owns the checkout

Agent Studio pipeline integration should reference a library, run named analyses over a repository path, and receive Quality Studio findings directly. The API remains a host and projection layer; the UI remains optional.

Delivered decision. Package the existing analysis library as QualityStudio.Analysis.Core, expose a narrow in-process runner, and prove it through quality-cli. Keep the code in this repository for now. Extraction is a separate operator decision.

HTTP-only leakage found and removed

AgentStudioTaskClient was stored in the analysis project even though only QualityStudio.Api registered and called it. It performs Agent Studio HTTP requests and models handover/import payloads, so it now lives in the API host with its tests. Remaining HttpClient use in the core is limited to resolving the pinned Gitleaks tool; it is analysis infrastructure, not an HTTP API or UI dependency. The core project has no Microsoft.AspNetCore reference.

The dependency direction is one way: hosts depend on the core. The core accepts a repository path, named analysis definitions, per-analysis configuration, cancellation, and an opt-in metadata persistence flag. It returns execution provenance and QualityFindingEnvelope values. It does not register repositories, authenticate requests, start a server, commit Git state, or project findings for the UI.

Stable first-slice surface

var result = await new QualityAnalysisRunner().RunAsync(
    new QualityAnalysisRequest(
        repositoryPath,
        [new QualityAnalysisDefinition("boundaries", configuration)],
        RepositoryId: repositoryId));

Built-in names cover boundaries, coverage, dependencies, ESLint, Gitleaks, Roslyn, SARIF, and TypeScript. Custom IReviewSensor implementations can be registered in process. That seam lets QS-90 remain versioned content: a host loads the selected rule library and supplies its resolved configuration or rule-backed sensor without importing UI or transport concerns into the core. Rule id, version/hash, and producer provenance should travel with findings as that library matures.

3. Operator question 1: is the core useful without the UI?

Yes.

Agent Studio pipeline · AGT-2655

A server-side step references the NuGet package, passes the already-present checkout path and pipeline configuration, and maps returned finding envelopes into later pipeline state. No Quality Studio server round trip is needed.

quality-cli

quality analyze . --analysis boundaries calls the same facade in process and emits the complete JSON result. This implementation is the proof caller.

CI

A small .NET test or runner can invoke selected analyses, retain provenance, serialize findings, and apply its own severity gate. The UI can ingest those findings later.

For those consumers the package must include the stable runner/request/result contract, the QS finding model and JSON vocabulary, named analysis discovery, sensor implementations and process adapters, cancellation and availability reporting, provenance, embedded prompts/catalogues needed by shipped analyses, and a configuration seam for repository-owned rule content. External analyzer binaries remain explicit runtime prerequisites. API auth, HTTP DTOs, UI projections, repository registry state, and Agent Studio transport must not be included.

4. Operator question 2: extract to a separate repository?

Do not extract now.

CriterionStay in this repository while…Extraction signal

Public-repository policyCore code, embedded prompts/catalogues, QS-90 rule content, and release provenance share this repository's policy.The operator has decided which code and rule content may be public, where security-sensitive or licensed content lives, and who owns disclosure and releases.

Recommendation: publish the package from this repository, integrate AGT-2655, and observe two or three release cycles. Return to the extraction decision once at least two independently deployed consumers pin package versions and the public-repository decision is recorded. Extraction itself is intentionally absent from QS-91.
