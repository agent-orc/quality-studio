Quality Studio Style Guide

A calm, practical standard for controls and compact admin surfaces. The guide turns the shared Agent Studio admin language into reviewable Quality Studio patterns.

Design lineage

This dossier derives from agent-taskboard/docs/operations/admin-design-guideline/, especially ADM-01, ADM-02, ADM-04, ADM-06, ADM-08, and ADM-09. It extends that language to controls; it does not invent a second design world.

How to use this guide

Use the smallest pattern that states the action or fact. Read semantic theme and spacing tokens, preserve the same structure in light and dark themes, and keep operator surfaces compact. Every changed surface should be added to Applied surfaces with its implementation and evidence references.

Buttons and add affordances

Primary, secondary, ghost, and additive actions with explicit visual do and do-not examples.

Inputs, selects, and numbers

Aligned field rows, persistent labels, helper text, dropdowns, and scaled token-count syntax.

Notices, density, and modals

Flat notices, tokenized spacing, internal modal scroll, and sticky action footers.

Applied surfaces

A growing implementation register, beginning with Onboard and Configure repository.

ActionsOne primary action per local decision. Secondary and ghost actions retain a solid, intentional boundary where needed.ADM-04, ADM-06
FormsLabels stay above controls. Helpers occupy a consistent row below the control and name units.ADM-04, ADM-08
NoticesAcute notices use a full-width tint, one dot, one statement, and at most one action.ADM-02

Contribution contract

  1. Start with the shared tokens and an existing control pattern.
  2. Add a visual do and do-not pair when a new reusable pattern is introduced.
  3. Verify relevant widths, both themes, focus order, and keyboard scrolling.
  4. Register the shipped surface on Applied surfaces.
