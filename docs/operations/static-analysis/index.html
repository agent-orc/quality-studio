Put deterministic facts before model judgement

Quality Studio already has analyzer and security sensors, but the orchestration still mixes machine facts, prompt context, and review findings. This dossier defines a selective preflight for the repository's .NET 10 and Angular 20 stacks, with measured checks, explicit gate behavior, and token-economy acceptance criteria.

Approval requested

Approve a selective, snapshot-bound preflight in the API/backend before every review sweep. Run configured checks once, persist their facts separately, skip only the model operation whose subject is invalid, and send compact context only when judgement is still useful. 01Decision and options

The decision is not whether to add static analysis from zero. Quality Studio already registers Roslyn, SARIF, ESLint, TypeScript, dependency, Gitleaks, boundary, and coverage sensors. The decision is where those checks execute, which outcomes stop a model call, and how much of each result enters a prompt.

OptionBehaviorAssessment
A. Context onlyKeep running sensors and attach complete result objects to model prompts.Close to the current analyzer path. It preserves judgement but spends tokens on machine prose, undercounts preflight cost, and cannot stop a known-invalid operation.
B. Hard gate all findingsAny deterministic finding prevents model review.Maximizes immediate savings but suppresses useful logic, security, and performance judgement for warnings and known advisories. It conflicts with the risk-floor policy.
C. Selective preflight recommendedRun once per snapshot; persist facts; block only invalid subjects; compact remaining context; measure avoided calls and token deltas.Reuses current sensor and run contracts, keeps findings inspectable, and saves spend without claiming deterministic checks replace semantic review.
D. External analysis serviceMove checks and findings to a new platform service.No repository evidence justifies a new deployment boundary. The API already owns review orchestration and process execution.

Recommendation

Choose C. Make the API/backend the preflight owner; keep worker CLIs free of Git operations. Preserve existing review sidecars, sensor provenance, grade caps, run store, usage ledger, and report projection while correcting execution frequency and prompt composition.

Snapshot equality is mandatory

Preflight facts apply only to the subject/config/tool-version tuple they measured. If source or lock content changes before a model operation, invalidate the cached projection and rerun the affected checks. A stale pass cannot authorize a model call.

Execution ownership

  • API/backend: plan, run, cache, normalize, gate, estimate, expose progress, and write review/run artifacts atomically.
  • Sensor processes: execute pinned repository commands without a shell and return bounded stdout/report files.
  • Model runner: receives the source and compact relevant facts only after the gate; it never launches linters or mutates the workspace.
  • Platform-owned pipeline: stages/commits approved repository artifacts. Quality Studio and worker CLIs do not commit, push, merge, or manage task worktrees.

07.3 Savings that can be stated now

  • Avoided invalid operation: a compiler-blocked call saves that operation's exact preflight estimate. The current editor.html file estimates 4,283 input + 857 output tokens for code review; a compile error at that subject should stop that spend until fixed.
  • Current project-performance gate: the Angular performance aggregate alone is 66,100 estimated input tokens. The checked-in production budget currently fails, so deferring that aggregate until the deterministic error is fixed avoids that spend without lowering the later model route.
  • Prompt compaction: the current frontend dependency sensor response is 17,450 characters for 24 findings. It is evidence of payload scale, not a direct token count. A result hash plus IDs/counts should replace full advisory prose in the prompt.
  • Execution savings: moving Gitleaks/dependency collection out of each file operation removes repeated repository processes. This reduces review wall time and load, not model tokens.
  • Clean-check payload: a clean operation needs no full sensor provenance in its prompt. Full provenance remains in preflight/review evidence.

No unsupported percentage claim

The repository has no committed usage entries for a retrospective before/after comparison, and current estimates omit executed sensor context. S5 must run matched snapshots and publish actual input/output usage, avoided calls, static runtime, and estimate deviation. Do not present the arithmetic above as measured savings.

07.4 Model-routing boundary

The canonical routing policy selects the cheapest route that clears the correctness floor and prohibits quota/cost from lowering hard floors. Deterministic preprocessing changes evidence volume and can prevent an invalid operation; it does not justify a weaker model for the remaining semantic review. Any later routing change requires controlled outcome evidence, not prompt-size arithmetic.

09Approval guardrails

  1. Model correctness floor is invariant. Static checks can block an invalid operation or shrink context; they cannot select a cheaper model/thinking level.
  2. Exact subject first. Every fact is bound to source, config, tool, and lock hashes. Change invalidates before model use.
  3. Unavailable is visible. A missing executable, formatter, report, network audit, or parse failure cannot return pass.
  4. Machine facts remain machine facts. The model cannot contradict, weaken, or duplicate advisories, secret matches, compiler errors, or budget values.
  5. Selective means narrow. A file compiler error blocks that file operation; a project budget error blocks the project performance aggregate. Warnings do not erase semantic review.
  6. Baselines are regression filters. They label current style/complexity debt; they never suppress a new fingerprint or rewrite historical observations.
  7. Prompt output is bounded. Clean checks contribute no verbose payload; compact finding context has a 2,000-character per-operation ceiling with overflow referenced by result hash.
  8. Secrets never enter prompts. Gitleaks content stays redacted and standalone.
  9. Backend owns workspace handling. Commands run without a shell, paths remain confined, and no CLI/agent performs Git lifecycle operations.
  10. Savings are measured, not inferred. Publish actual matched usage before a percentage claim or routing proposal.

landed

The API now collects every enabled analyzer and security sensor once into a versioned, immutable PreflightSnapshot before model scheduling.
