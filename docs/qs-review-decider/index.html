Quality Studio as the review decider for Agent Studio

Should Quality Studio replace the model review aspects as the source and the decider for code reviews in the Agent Studio pipeline? This template compares three options with measured cost, names what Quality Studio must fix first, and defines a two-week trial whose numbers make the call.

00 Decision summary

Recommendation: option B, proven by a paired trial

Quality Studio decides the code-quality aspect only. The model aspects for requirement fit, tests and evidence, and documentation impact stay. Agent Studio's review policy, fix rounds and gates stay. Start on Agent Studio once the entry gate closes: QS-110, QS-111, QS-113 and QS-116 merged, QS-117 delivered. Run one week in shadow, then one week with QS deciding and the model aspect in reverse shadow.

Three measured facts carry the decision:

  1. The model aspects are not where review time goes. On Agent Studio (15 to 25 September) the verify commands take a median 28.9 minutes per review. All four aspects together take 1.85 minutes. No option saves meaningful host minutes by replacing aspects.
  2. The code-quality aspect is the model decider that matters. It blocked in 50 of 83 Agent Studio ProductFailure reviews and was the only blocker in 38. Requirement fit and tests-and-evidence blocked in none; they raised concerns.
  3. Quality Studio is not yet a safe decider. Its standing grade and its deterministic "regression" flag are not bound to the change: 11 of 20 recent QS transitions were flagged as regressions, mostly for new endpoints. Isolation (D12), hidden builds (D7) and analyzer profiles (D8–D10) are still open on branches, and QS-117 has not started.

What you approve today: option B as the target, the gap list in Prerequisites as the entry gate, and the trial design in Recommendation. Option C is rejected for now: Quality Studio has no input for requirement fit.

01 Alternatives

Today every Agent Studio Remote Review materializes the exact Result-SHA, runs the verify commands (build, three .NET test suites, frontend build, tests and lint), then runs four model aspects on the diff: code-quality, tests-and-evidence, requirement-fit and documentation-impact. The outcome is Pass, ProductFailure or ReviewInfra. ReviewFollowUpPolicy turns a block into a fix round and a concern into one automatic concern round, then re-reviews in scope. The aspects are not all Claude: across 1,032 aspect runs since 15 September, 594 ran on Claude models and 438 on GPT models, per project routing.

Agent Studio also already runs Quality Studio's analysis core in-process as a local pipeline step (named-rule passes). Its medium-or-higher findings feed the steered-retry loop. That step is not part of Remote Review and has no verdict.

A · Quality Studio as an additional advisory aspect

Pipeline change. One more review-library step runs the QS change review on the fenced Result-SHA and attaches its findings to the report. The verdict, fix rounds and gates are unchanged. This is QS-W6 Slice 3, already approved on 11 August and not yet built in Agent Studio.

Cost per review. Host time rises by one diff-bound QS agent call plus cached sensors. The code-quality aspect is the comparable call at 0.95 minutes median and 2.2 minutes p90, so expect +1 to +3 minutes (inferred). Model tokens rise by roughly one aspect's worth. Before QS-111 lands, every QS run also re-runs all sensors on the whole repository, including a full Release build when the build sensor is on (D7).

Determinism. The outcome does not change, because nothing QS says can block.

Blind spots. The current ones remain. Advisory findings in a report with many rows tend to go unread; the 09-28 run produced 470 findings, of which six were genuine highs.

Rollout risk. Low. Cost rises; there is no effect on throughput or quality. On its own it does not answer Robert's question.

B · Quality Studio decides the code-quality aspect

Pipeline change. A QS verdict step replaces the model code-quality aspect as the producer of the code-quality verdict (pass, concerns, block with citation). The other three aspects stay model-based. The verdict enters ReviewFollowUpPolicy and the citation contract unchanged. A QS failure is ReviewInfra, never Pass. Per-project switch: off, shadow, decide.

Cost per review. Neutral: one model call is replaced by one diff-bound QS call. Deterministic rule findings cost no tokens. SARIF from the plane's own build step avoids a second build. The real lever is fix rounds. ProductFailure was 142 of 277 decided Agent Studio reviews since 22 September. Each avoidable code-quality block costs a coding round and a full re-review (median 54 minutes of host time).

Determinism. Better than today for the deciding findings. Rule findings are reproducible for the same subject SHA, rule-set hash and QS version. Model-judged QS findings may block only with a rule id, a changed-line anchor and a citation.

Blind spots. Code-quality defects outside the rule catalogue now depend on the QS agent judgement: only 8 of 33 rules were cited across 526 findings. Standing debt in untouched code is never blocking; it stays with QS sweeps and handover cards.

Rollout risk. Medium and bounded. It changes the decider behind 46% of Agent Studio product failures, but shadow, reverse shadow and the per-project switch make it reversible within one attempt.

C · Quality Studio as the sole decider with a verdict contract

Pipeline change. All four model aspects are removed; one QS verdict decides the semantic part of the review. The verify commands stay: QS does not run test suites.

Cost per review. Saves at most the four aspect calls: 1.85 minutes median of a 37-minute review, and about 1.9% of pipeline tokens in the July corpus. The 80 to 140 minutes named on the card are verify-command time and queue time; they are unchanged.

Determinism. No better than B. Requirement fit and documentation impact would still need a model judgement, now inside QS.

Blind spots. QS reviews code, not the card. It has no task text or acceptance criteria, so "did the delivery do what was asked" has no input. Its change aspects are risk, test evidence, scope discipline and architecture drift. There is no coverage data for Agent Studio yet, so risk scores are empty (QS-115).

Rollout risk. High. It is one point of failure for every review. It contradicts the QS-W6 boundary that Studio owns task policy and QS never moves a task. It cannot be run as a like-for-like shadow for the aspects QS does not model.

02 Recommendation

Recommended default: B, entered through a two-week paired trial on Agent Studio

Quality Studio becomes the source and decider for the code-quality aspect. Agent Studio keeps requirement fit, tests and evidence, documentation impact, the verify gates, and every policy that turns a verdict into a fix round or a lane move. The trial decides whether B is extended to every project and whether the model code-quality aspect is retired (QS-W6 Slice 5).

Reasoning

  • B targets where the model decides. The code-quality aspect is the only model aspect that blocks in practice: 50 of 83 product failures, 38 as the only blocker. Replacing the others would change almost nothing about decisions.
  • B keeps the parts QS cannot see. Requirement fit needs the card text and the results inventory; QS has neither. C would give the decision to a component that has no input for part of it.
  • The time argument is fix rounds, not aspect minutes. Aspects are about 5% of review host time. Each avoided false block saves a whole re-review and a coding round. Agent Studio cards take a median 2 and a p90 6 remote grades.
  • B fits the QS-W6 boundary. QS produces an immutable, cited verdict; Studio policy applies it. No second scheduler, and QS never moves a task.
  • A is the first week of B, not an alternative. The shadow week is option A with a paired measurement attached.

Acceptance criteria

Entry gate (before day 1). QS-108, QS-109 (both on main), QS-110, QS-111, QS-113 and QS-116 are merged to main. QS-117 is delivered. The first three implementation tasks of this Dossier are delivered. A dry run on ten historical Agent Studio subjects produces ten schema-valid verdicts, and a rerun of each gives identical deterministic findings.

Success at the end of week 2, measured on at least 150 reviewed subjects with at least 30 adjudicated QS blocks:

  1. Review minutes. The median claim-to-report of decided reviews rises by no more than 3 minutes over the week-1 median. Review attempts per card do not rise over week 1.
  2. False blocks. At most 10% of adjudicated QS blocks are false blocks, and the QS rate is not higher than the model code-quality aspect's rate on the same adjudicated subjects.
  3. Escaped defects. No high-severity defect that the reverse-shadow model aspect blocked validly and QS passed. At most two such defects of lower severity. No trial delivery is the cause of a bug card or gate failure filed within 14 days of its integration.
  4. Reliability. The QS step yields ReviewInfra in no more than 2% of reviews. 100% of verdicts are schema-valid and bind the reviewed Result-SHA. An unparseable reply never becomes Pass.
  5. Cost. QS tokens per review are recorded with cache writes. Their median is no more than 1.5 times the week-1 median of the replaced aspect.

Stop rules (switch the project back to off the same day): QS ReviewInfra above 5% on any day; one confirmed high-severity escape; false-block rate above 25% after the first 20 adjudicated blocks.

After the trial. If it passes, enable B project by project and retire the model code-quality aspect under QS-W6 Slice 5 with its rollback window. If it fails, stay on shadow (A), fix the named rules or gaps, and repeat. C is not revisited until QS models requirement input and Agent Studio coverage exists.

Limits

  • The operator's evaluation file of 28 September is on the operator machine, not on the runner host. The counts "470 findings" and "six genuine highs" come from the QS-118 card; QS-112 names 526 findings for its rule count. Both are quoted, not reconciled. D11, D13 and D14 are unverified here.
  • QS-114 and QS-117 have no card text on the runner host. The QS-117 scope used here (verdict contract, diff-bound rule review) is taken from the QS-118 card.
  • No labeled data for false blocks or escaped defects exists for either the model aspects or QS. That is why the recommendation is a paired trial rather than a switch.
  • Journal durations include worker overhead; medians of steps and totals come from overlapping but not identical attempt sets.
  • The canonical article template docs/app/templates/article-document-v2.html and the fallback style are absent from this repository. The v2 style block was copied from the Agent Studio repository at 742936e05.
