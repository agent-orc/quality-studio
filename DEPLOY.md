# Website source and publication

The public [Quality Studio website](https://agent-orchestrator.dev/quality/) is maintained in the separate `quality-studio-website` repository (`RobertMischke/quality-studio-website`, private). Its `main` branch is the live website source. It includes the existing German/English pages, screenshots, and model catalogue.

The `website/` directory in this product repository is a reference page. Publishing this directory to this repository's `deploy` branch does **not** update the public website. A successful reference-export workflow is not evidence of a live website release.

## Shared review policy

Named rules in `rules/` and metric definitions in `rules/review-methodology.json` remain the product's authoritative review policy. The tool consumes the generated rule catalogue and metric reference. The separate website imports a versioned snapshot from those same sources with its documented sync command; German text is a translation of that policy, not a second set of rules.

When changing the policy, update its authoritative sources and run `npm run rules:sync` and `npm run rules:check` here. Then refresh and verify the separate website's policy snapshot and translations before publishing that website. Its README documents the consumer-side sync and checks.

## Public website release

1. Prepare and verify the change in the separate website repository, preserving both languages, existing pages, and assets.
2. Commit and push the reviewed website content to that repository's `main` branch.
3. The existing host timer updates its hosting manifest and pulls the configured site branches every five minutes, with up to thirty seconds of scheduling jitter. It activates a release through a symlink swap.
4. Verify `https://agent-orchestrator.dev/quality/`, its assets and links, and the new content after the host sync. Compare the served HTML with the published website commit before calling the change live.

The private Agent Orchestrator website meta-repository records the active site under `hosting/sites.json`: slug `quality`, path `/quality/`, source `RobertMischke/quality-studio-website`, branch `main`. This existing registration serves the standalone website; publishing a product reference snapshot does not change it.

## Product reference export

The workflow file `deploy-website.yml` retains its existing trigger: changes under `website/` on product `main`, or manual dispatch. It publishes the contents of `website/` as the root of a single-commit `deploy` branch in **this product repository**. The review reference inside that page is generated by `npm run rules:sync`; hosting the resulting static files requires no runtime build.

The workflow uses the repository's default `GITHUB_TOKEN` with `contents: write`. If this reference branch needs recovery, rerun the workflow. Reconstructing it manually must follow the same directory boundary: publish only `website/`, never the product repository root. This repairs the reference export, not the standalone website's live release.
